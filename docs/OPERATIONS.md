# Local operations and limits

Local-first development, not a deployed or production-approved service. Use Node 22.23.1 on persistent disk. SQLite is experimental in this runtime; validate a supported pinned database/runtime before public launch. No Vercel filesystem persistence claim.

After `npm ci && npm run check`, run `npm run owner:create -- owner@example.com` interactively. The passphrase is read with terminal echo suppressed, never as a shell argument. This is an operator-provisioned local account; it is not proof of email verification. Public registration, organization membership management, external email verification, self-service account export/deletion, password recovery, API keys and billing remain later gates. Researchers and separate tenants are exercised in isolated tests.

`npm run dev` builds and starts http://127.0.0.1:4310. On startup migrations apply transactionally and isolated fixtures are seeded. Public discovery is empty until a permitted summary is explicitly published. Select Explore samples for fixtures. Never import the sample inventory as real opportunities.

Import via UI (owner) or `npm run import -- OWNER_EMAIL PATH json|csv`. JSON array/CSV headers need domain, source, sourceUrl, externalId, licenseRef, observedAt. Optional: category, price, currency, deadline, availability (unknown/registered/possibly_available), extensionTlds (JSON array or pipe-separated CSV), history, confidence, trendVelocity, risk. Missing metrics null. Manual imports cannot confirm registrar purchase availability. JSON booleans `notificationsAllowed` and `publicAllowed` are false unless explicitly true. CSV cannot silently turn text `true` into permission. Public permission additionally requires licenseRef in `APPROVED_PUBLIC_LICENSES` (pipe-separated, owner-reviewed); this allowlist is empty by default. Importing is not legal authorization. Owner review resets after an updated observation. Raw imports are private.

Jobs are persisted and claimed with a lease. Run `npm run queue -- digest`, then `npm run worker`. To send one pending reviewed, consented real alert, queue `npm run queue -- telegram`, then `npm run worker`. No message is sent when Telegram is disabled. Configure a persistent host scheduler to run these commands periodically; no cron is installed by this build. A once-per-five-minutes invocation is sufficient to catch the configured daily hour. Instant means the next configured worker tick. A public serverless deployment needs a durable remote queue/database instead.

Jobs retry with bounded backoff/jitter and enter dead-letter after three attempts. SQLite locks protect claims. Source endpoints cannot be activated just by setting their flag: GoDaddy/Dynadot are blocked adapters, RDAP is a parser/bootstrap contract with fixtures only. Cost reservations are tested; paid upstream transports do not exist. Each future live connector must reserve its budget before requests and implement verified per-host terms, cache TTL, retry/circuit policy and concurrency limits. No arbitrary URL fetching is provided.

Telegram setup: create the single owner bot with official BotFather; set TELEGRAM_BOT_TOKEN, TELEGRAM_BOT_USERNAME, TELEGRAM_WEBHOOK_SECRET (16+ URL-safe characters) and CREDENTIAL_ENCRYPTION_KEY (32 random bytes as 64 hex digits) in .env/secrets. Generate locally with `openssl rand -hex 32`; do not paste keys in Git or logs. Set TELEGRAM_ENABLED=true only after HTTPS hosting exists. Register the webhook using Telegram setWebhook with URL <PUBLIC_ORIGIN>/api/telegram/webhook and secret_token matching TELEGRAM_WEBHOOK_SECRET; keep the bot token out of shell history, arguments and logs by using a protected secret input. Official docs: https://core.telegram.org/bots/api#setwebhook and https://core.telegram.org/bots/features#deep-linking . No webhook was registered during this build. Then sign in, Account & delivery, Link Telegram, open the bot and Start. No user needs a personal bot token. Link code expires after 10 minutes, private destination verified, encrypted at rest; disconnect cancels pending messages.

A normal send is free subject to Telegram limits; `allow_paid_broadcast=false`. Company-gap alert promotion is blocked until M3 alternative-use evidence and human-review gates. Only reviewed, fresh (<24h), notification-permitted nonfixture candidates can enter the outbox. The global daily ceiling is 20, additionally restricted by each saved rule. UTC quota day and user-local digest day are distinct and documented. Material input fingerprint prevents refresh-only duplicates. Same observation cannot alert twice per user/rule. Ambiguous send becomes uncertain and is never blindly retried; reconcile Telegram acceptance before any manual recovery. Provider-rejected messages become failed; refined 429-specific retry and sender-wide rate coordination are M7 hardening gaps. Crashed sending rows also require manual reconciliation, never automatic resend.

Backup / migration rollback: stop every server and worker using the database; open SQLite to checkpoint WAL, then copy the database and any WAL/SHM as a consistent set to protected storage. Verify restore on a temporary copy before deployment. Numbered migrations are forward-only; rollback means restore the validated pre-migration backup and previous code. No destructive down migration is run automatically. Migrations 001–003 are tested on a fresh DB and a reopened persistent DB. Private backups contain personal data; restrict access and set retention before hosting.

External source outages: connectors stay disabled; manual import and sample mode continue. Inspect /sources and owner jobs. Public/API rights, license retention and source-specific data deletion must be reviewed before activating each source. Admin audit log is redacted but local retention/deletion automation remains M7 work. Never fetch or automate ExpiredDomains.net.
